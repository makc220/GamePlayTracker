# Робочі нотатки

## ЛР 2

* `Title`, `Genre` та `Developer` мають тип `string`, оскільки це текстові значення.
* `ReleaseDate` має тип `DateOnly`, оскільки для дати випуску гри час доби не потрібен.
* `ReleaseYear` має тип `int`, оскільки рік є цілим числом.
* `Description` має тип `string?`, оскільки опис гри може бути відсутнім.
* Окремий `enum` на цьому етапі не створюється, оскільки властивість зі скінченним набором станів з'явиться у типі `Playthrough`, який буде додано в наступних лабораторних роботах.

## ЛР 3

* Для роботи з базою даних SQLite використовується Entity Framework Core.
* `GamePlayTrackerContext` успадковується від `DbContext` і містить `DbSet<Game> Games`, який відповідає таблиці `Games`.
* База даних зберігається у файлі `gameplaytracker.db`.
* Для створення та оновлення схеми бази даних використовуються міграції Entity Framework Core.
* Перетворення `decimal` у `double` не потрібне, оскільки в моделі `Game` немає властивостей типу `decimal`. Таке перетворення знадобилося б для коректного зберігання та сортування десяткових значень у SQLite.
* Для роботи з EF Core та генератором сторінок у проєкті використовується локальний маніфест інструментів `.config/dotnet-tools.json`.

## ЛР 4

* `@page` — визначає URL-адресу, за якою доступна Razor-сторінка. Наприклад, `@page "/games"` задає маршрут до списку ігор.
* `@inject IDbContextFactory<GamePlayTrackerContext>`** — дає змогу сторінці отримувати фабрику контексту бази даних. За допомогою фабрики створюється контекст для виконання операцій із даними.
* `QuickGrid` та `Items` — компонент `QuickGrid` відображає записи у вигляді таблиці. Параметр `Items` визначає джерело даних для таблиці.
* `EditForm` та `@bind-Value` — `EditForm` використовується для введення й редагування даних, а `@bind-Value` забезпечує зв'язок полів форми з властивостями моделі `Game`.
* `OnValidSubmit` та `NavigateTo` — `OnValidSubmit` викликає обробник після успішної перевірки форми, а `NavigateTo` дає змогу перейти на іншу сторінку після виконання операції.

## ЛР 5

* Створено компонент `GameCard.razor` у каталозі `Components`.
* Параметр `Game` передає компоненту об'єкт гри для відображення його властивостей. Атрибут `[EditorRequired]` позначає цей параметр як обов'язковий для використання компонента в редакторі.
* Параметр `Caption` дає змогу передати підпис картки. Він має тип `string?`, оскільки підпис може бути відсутнім.
* Параметр `ShowDetails` визначає, чи показувати додаткову інформацію про гру. За замовчуванням його значення — `true`.
* Компонент використовується на сторінках `Details.razor` і `Delete.razor` із різними значеннями параметрів. Це дає змогу повторно використовувати розмітку та змінювати вигляд картки без дублювання коду.
* У файлі `Components/_Imports.razor` додано `@using GamePlayTracker.Models` для доступу до класу `Game` у компонентах.
